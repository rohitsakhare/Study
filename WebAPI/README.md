# ObservabilityDemo

A .NET 9 product catalog API demo with a complete observability stack built using Docker Compose.

## Overview

This repository is a reference implementation for an observability-driven ASP.NET Core service.
It includes a product API, a PostgreSQL database, OpenTelemetry instrumentation, a collector, and monitoring tools.

## What this repository contains

- `ProductService/` - ASP.NET Core web API project
- `docker-compose.yml` - Docker Compose service definitions for the demo stack, including PostgreSQL, Redis, RedisInsight, OpenTelemetry, Prometheus, Jaeger, and Grafana
- `otel-collector.yaml` - OpenTelemetry Collector configuration
- `prometheus.yml` - Prometheus scrape configuration

## Architecture and component roles

### productservice

- Runs the `ProductService` ASP.NET Core API
- Uses EF Core with PostgreSQL for data persistence
- Registers Redis distributed cache via `StackExchangeRedisCache`
- Exposes product management endpoints under `/api/products`
- Implements caching for `GET /api/products/{id}` and cache invalidation on update/delete
- Emits telemetry using OpenTelemetry tracing and metrics
- Sends telemetry to the collector at `http://otel-collector:4317`
- Uses Serilog console logging with trace/span enrichment
- Serves OpenAPI documentation and Scalar-based API reference UI

### product-db

- PostgreSQL database container using `postgres:16.3`
- Stores product records in the `productsdb` database
- Persists state in the Docker volume `product_data`

### redis

- Runs Redis cache using `redis:7-alpine`
- Provides distributed caching for product lookup results
- Accessible within the Compose network as `redis:6379`

### redis-insight

- Runs RedisInsight UI using `redis/redisinsight:latest`
- Helps inspect cache contents and latency
- Exposes dashboard on `http://localhost:8001`

### otel-collector

- Receives OTLP telemetry from the API on gRPC `4317` and HTTP `4318`
- Processes traces and metrics using `memory_limiter` and `batch`
- Exports traces to Jaeger and metrics via Prometheus scraping
- Also provides a debug exporter for collector diagnostics

### prometheus

- Scrapes metrics exposed by the collector on `otel-collector:9464`
- Runs with a 5-second scrape interval
- Serves as the source of metrics for Grafana dashboards

### jaeger

- Visualizes distributed traces generated by the API
- Shows spans, timings, and request flow through the service

### grafana

- Connects to Prometheus to display dashboards
- Enables visual monitoring of metrics such as request counts and latency

## Configuration files and runtime details

### `docker-compose.yml`

- Defines the full demo stack: `product-db`, `productservice`, `otel-collector`, `prometheus`, `jaeger`, and `grafana`
- Uses `depends_on` with health checks so `productservice` waits for PostgreSQL readiness
- Exposes ports for local access and service communication across the Docker network
- Sets environment variables for the API connection string and ASP.NET Core URL

### `otel-collector.yaml`

- Receives OTLP telemetry on gRPC `4317` and HTTP `4318`
- Uses `memory_limiter` and `batch` processors to protect memory and improve throughput
- Exports traces to Jaeger and metrics to Prometheus
- Includes `debug` exporter to log collector internals in detail

### `prometheus.yml`

- Configures Prometheus to scrape the collector endpoint at `otel-collector:9464`
- Sets a short 5-second scrape interval for demo metrics responsiveness

### Code-level observability in `ProductService/Program.cs`

- Serilog is configured to enrich logs with environment, process, thread, trace ID, and span ID
- OpenTelemetry is registered with a resource service name of `product-api`
- Tracing configuration includes:
  - ASP.NET Core instrumentation
  - HTTP client instrumentation
  - OTLP exporter pointing to `http://otel-collector:4317`
- Metrics configuration includes:
  - ASP.NET Core instrumentation
  - runtime instrumentation for .NET metrics
  - OTLP exporter to the same collector endpoint
- Redis distributed cache is configured using `AddStackExchangeRedisCache`
  - connection string loaded from `Redis:ConnectionString`
  - cache instance name prefix `MyApi_`
- The app uses `db.Database.Migrate()` at startup to apply EF Core migrations automatically

## Redis caching behavior

- `GET /api/products/{id}` first checks Redis cache for `product:{id}`
- If cached, the API returns the cached product with a `source: cache` indicator
- On cache miss, the product is loaded from PostgreSQL and then cached for 10 minutes
- `PUT /api/products/{id}` and `DELETE /api/products/{id}` remove the cached product entry after mutation

## How telemetry flows

1. The API is instrumented with OpenTelemetry and exports OTLP to the collector.
2. The collector processes telemetry data and sends traces to Jaeger.
3. The collector exposes a Prometheus endpoint at `http://localhost:9464`.
4. Prometheus scrapes the collector and stores metrics.
5. Grafana queries Prometheus to build dashboards.

## Product model

The service uses a simple product entity with the following fields:

- `Id` - GUID primary key
- `Name` - product name
- `Price` - decimal product price
- `Stock` - integer inventory quantity
- `CreatedAt` - UTC creation timestamp

## API endpoints

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/products/health` | Returns a simple `running...` health response |
| `GET` | `/api/products` | List all products |
| `GET` | `/api/products/{id}` | Get a specific product by ID |
| `POST` | `/api/products` | Create a new product |
| `PUT` | `/api/products/{id}` | Update an existing product |
| `DELETE` | `/api/products/{id}` | Delete a product |

### Example requests

Create a product:

```powershell
curl -X POST http://localhost:5001/api/products \
  -H "Content-Type: application/json" \
  -d '{"name":"Laptop","price":1299.99,"stock":10}'
```

Update a product:

```powershell
curl -X PUT http://localhost:5001/api/products/{id} \
  -H "Content-Type: application/json" \
  -d '{"name":"Laptop Pro","price":1499.99,"stock":8}'
```

Delete a product:

```powershell
curl -X DELETE http://localhost:5001/api/products/{id}
```

## Getting started with Docker Compose

Start the full stack from the repository root:

```powershell
docker compose up --build
```

If your Docker version uses the older command, run:

```powershell
docker-compose up --build
```

The first startup may take a few minutes while images download and the database initializes.
The API automatically applies EF Core migrations at startup.

## Service URLs

- API: `http://localhost:5001`
- OpenAPI docs: `http://localhost:5001/openapi`
- Prometheus: `http://localhost:9090`
- Jaeger UI: `http://localhost:16686`
- Grafana: `http://localhost:3000`

## Grafana default login

- Username: `admin`
- Password: `admin`

## Running the API locally

To run the API without Docker:

```powershell
cd ProductService
dotnet run
```

You must point the application to a running PostgreSQL instance via `appsettings.json` or environment variables.

## Troubleshooting

- If the API fails to connect to the database, confirm `product-db` is healthy and reachable from the `productservice` container.
- If telemetry is missing, verify the API is exporting to `http://otel-collector:4317` and that the collector container is running.
- If Prometheus has no metrics, verify scrape target `otel-collector:9464` is available.
- If dashboards show no data, confirm Grafana is connected to Prometheus and the Prometheus data source is healthy.

- use Prometheus and Grafana for metrics monitoring

- deploy and run a local observability stack with Docker Compose
